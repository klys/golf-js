NOISE GOLF 2D WEB 0010 + PATCH 0001
MANUAL COMPLETO DE DESPLIEGUE HTTPS / VPS
===========================================

OBJETIVO
--------
Este paquete del juego es un cliente/host web estático (HTML + CSS + JavaScript).
NO necesita Node, npm, Bash, BAT ni ejecutables para funcionar en el VPS.

El multiplayer es RELAY ONLY:
  1) El navegador consulta el Server Relay público para preflight, discovery y señalización.
  2) Después, cuando WebRTC lo permite, el gameplay viaja Host <-> Cliente.
  3) El Relay NO simula la física del golf.

ARQUITECTURA RECOMENDADA
------------------------
  https://golf.tudominio.com/        -> NGINX sirve el juego estático
  wss://relay.tudominio.com/         -> NGINX proxy WebSocket hacia Node
  Node Relay interno                 -> 127.0.0.1:8787

El puerto 8787 NO necesita exponerse a Internet si NGINX y el Relay están en el mismo VPS.
Solo necesitas publicar normalmente TCP 80 y TCP 443.


1. SUBIR EL JUEGO
-----------------
Descomprime el juego y copia TODO su contenido a una carpeta pública del VPS.
Ejemplo recomendado:

  /var/www/noise-golf/

La estructura debe conservarse:

  /var/www/noise-golf/
  |-- .env
  |-- .env.example
  |-- index.html
  |-- css/
  |-- js/
  |-- INSTRUCCIONES_VPS_ES.txt
  |-- VERSION.txt
  `-- ...

MUY IMPORTANTE: conserva el archivo oculto .env.

Ejemplo de permisos en Ubuntu/Debian:

  sudo chown -R www-data:www-data /var/www/noise-golf
  sudo find /var/www/noise-golf -type d -exec chmod 755 {} \;
  sudo find /var/www/noise-golf -type f -exec chmod 644 {} \;


2. CONFIGURAR EL .env DEL JUEGO
-------------------------------
Edita:

  /var/www/noise-golf/.env

Configuración recomendada para producción HTTPS:

  NG_ONLINE_ENABLED=true
  NG_MAX_PLAYERS=16

  NG_RELAY_URL=wss://relay.tudominio.com
  NG_RELAY_CONNECT_TIMEOUT_MS=6500
  NG_PREFLIGHT_TIMEOUT_MS=6500

  NG_SNAPSHOT_HZ=20
  NG_RELIABLE_PING_SECONDS=2
  NG_REQUEST_TIMEOUT_MS=6500
  NG_WEBRTC_CONNECT_TIMEOUT_MS=14000

  NG_CLIENT_INTERPOLATION_MS=70
  NG_CLIENT_MAX_EXTRAPOLATION_MS=125
  NG_CLIENT_SMOOTHING_RESPONSIVENESS=18
  NG_CLIENT_SNAP_DISTANCE=210

  NG_PUBLIC_ICE_SERVERS_JSON=[]

  El cambio de mundo tiene un enfriamiento fijo de 60 segundos.
  NG_MAP_VOTE_TIMEOUT_SECONDS=30

Si el juego usa HTTPS, NG_RELAY_URL debe usar wss:// y NO ws://.

SEGURIDAD IMPORTANTE:
El .env DEL JUEGO es PUBLICO porque el navegador necesita descargarlo.
NO introduzcas:
  - contraseñas privadas;
  - API keys secretas;
  - claves privadas TLS;
  - credenciales permanentes de servicios;
  - secretos administrativos.


3. CONFIGURACION DEL RELAY PARA HTTPS
-------------------------------------
En el .env PRIVADO del Server Relay utiliza, como base:

  HOST=127.0.0.1
  PORT=8787

  PUBLIC_NAME=Noise Golf Relay
  PUBLIC_WS_URL=wss://relay.tudominio.com

  TRUST_PROXY=true
  ALLOW_FILE_ORIGIN=false
  ALLOWED_ORIGINS=https://golf.tudominio.com

El Relay debe arrancar correctamente y mostrar algo equivalente a:

  Noise Golf Relay escuchando en 127.0.0.1:8787

Antes de configurar NGINX puedes comprobarlo localmente en el VPS:

  curl http://127.0.0.1:8787/health

Debe responder un JSON con ok=true.


4. INSTALAR NGINX
-----------------
En Ubuntu/Debian:

  sudo apt update
  sudo apt install nginx

Comprueba:

  sudo systemctl status nginx


5. CONFIGURACION NGINX COMPLETA
------------------------------
Crea, por ejemplo:

  sudo nano /etc/nginx/sites-available/noise-golf

Usa esta base y sustituye tudominio.com por tu dominio real:

------------------------------------------------------------
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    listen [::]:80;

    server_name golf.tudominio.com;

    root /var/www/noise-golf;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # El cliente necesita leer exclusivamente SU .env publico.
    location = /.env {
        default_type text/plain;
        add_header Cache-Control "no-store, no-cache, must-revalidate" always;
        try_files /.env =404;
    }

    # Bloquear el resto de dotfiles.
    location ~ /\.(?!well-known/) {
        deny all;
    }
}

server {
    listen 80;
    listen [::]:80;

    server_name relay.tudominio.com;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
------------------------------------------------------------

Activa el sitio:

  sudo ln -s /etc/nginx/sites-available/noise-golf /etc/nginx/sites-enabled/noise-golf

Si el enlace ya existe, no lo crees otra vez.

Comprueba SIEMPRE antes de recargar:

  sudo nginx -t

Si la prueba es correcta:

  sudo systemctl reload nginx


6. DNS
------
En tu proveedor DNS crea dos registros A hacia la IP publica del VPS:

  golf.tudominio.com   -> IP_PUBLICA_DEL_VPS
  relay.tudominio.com  -> IP_PUBLICA_DEL_VPS

Antes de solicitar certificados, ambos nombres deben resolver al VPS.

Puedes comprobarlo desde otra maquina con:

  nslookup golf.tudominio.com
  nslookup relay.tudominio.com


7. HTTPS CON CERTBOT
--------------------
Una vez NGINX y DNS funcionen por HTTP, instala Certbot según tu distribución.
Ejemplo habitual en Ubuntu con snap:

  sudo snap install --classic certbot

Si es necesario:

  sudo ln -s /snap/bin/certbot /usr/local/bin/certbot

Solicita certificados para AMBOS dominios:

  sudo certbot --nginx -d golf.tudominio.com -d relay.tudominio.com

Activa la redirección HTTP -> HTTPS cuando Certbot la ofrezca.

Después verifica renovación:

  sudo certbot renew --dry-run


8. COMPROBACIONES DESPUES DE HTTPS
----------------------------------
Prueba en este orden:

A) Juego:
  https://golf.tudominio.com/

B) Configuracion publica del juego:
  https://golf.tudominio.com/.env

Debe mostrar el .env y contener:
  NG_RELAY_URL=wss://relay.tudominio.com

C) Health del Relay:
  https://relay.tudominio.com/health

D) Desde consola:
  curl https://relay.tudominio.com/health
  curl https://golf.tudominio.com/.env

E) Recarga el juego.
El preflight debe validar:
  - Configuracion cliente/host: OK
  - Relay publico: OK
  - Compatibilidad de protocolo: OK
  - Directorio de partidas: OK

Solo despues se habilita ONLINE.
Si alguna comprobacion falla, el juego mantiene Offline disponible y bloquea Multiplayer.


9. FIREWALL RECOMENDADO
-----------------------
Si NGINX y Node estan en el mismo VPS:

  PUBLICAR:
    TCP 80
    TCP 443

  NO PUBLICAR:
    TCP 8787

Node escucha en 127.0.0.1:8787 y NGINX es el unico intermediario publico.


10. PRUEBA MULTIPLAYER
----------------------
1) Comprueba que el Relay Node esta ejecutandose.
2) Abre https://golf.tudominio.com/ en navegador A.
3) El preflight debe pasar.
4) Crea una partida.
5) Abre otro navegador/perfil/equipo.
6) Entra en Online, actualiza la lista y localiza la partida.
7) Unete y comprueba WebRTC.
8) Prueba Por Turnos.
9) Prueba Battle Royale.
10) Prueba Reconectar recargando UN CLIENTE sin usar "Desconectar y volver al inicio".

Para pruebas en una misma PC usa navegadores o perfiles diferentes para evitar compartir la misma identidad de localStorage.


11. RECONEXION
--------------
Si un CLIENTE:
  - recarga la pagina;
  - cierra accidentalmente la pestaña;
  - pierde la conexion sin salir explicitamente;

el juego conserva temporalmente la informacion de recuperacion.

Al regresar:
  1) se ejecuta de nuevo el preflight;
  2) se consulta el Relay;
  3) si la partida sigue existiendo aparece RECONECTAR;
  4) si ya no existe, la reserva local se limpia.

Si el jugador pulsa deliberadamente:

  DESCONECTAR Y VOLVER AL INICIO

la reserva se elimina y NO debe aparecer Reconectar.

El Host es autoritativo. Si el Host destruye su pestaña y desaparece la simulacion, no se fabrica una recuperacion falsa de un mundo que ya no existe.


12. POR TURNOS
--------------
- La camara sigue siempre la bola del jugador que tiene el turno.
- La bola/nombre del jugador de turno tiene prioridad visual cuando varias bolas se superponen.
- Los clientes que no tienen el turno observan al jugador activo.


13. BATTLE ROYALE - IDENTIDAD LOCAL (PATCH 0001)
------------------------------------------------
Battle Royale mantiene la camara de cada cliente sobre SU propia bola.

Ademas, desde PATCH 0001:
  - cada navegador marca exclusivamente SU propia bola;
  - la etiqueta local se dibuja por delante de las etiquetas de los otros jugadores;
  - muestra "TÚ · Nombre";
  - usa el color asignado al jugador como borde/puntero;
  - esta marca es SOLO visual y local;
  - no se transmite como autoridad ni modifica snapshots;
  - cada jugador ve su propia identidad resaltada en su propio cliente.

Esto evita perder la propia bola cuando muchos jugadores estan juntos.
Por Turnos NO utiliza la marca "TÚ" de Battle Royale; conserva la prioridad del jugador con turno.


14. SUAVIZADO / PREDICCION DE CLIENTE
-------------------------------------
El Host sigue siendo la unica autoridad de fisica.
Los clientes usan una capa visual para reducir sensacion de lag:
  - interpolacion;
  - extrapolacion corta limitada;
  - correccion adaptativa;
  - prediccion visual inicial del tiro local;
  - snap autoritativo ante cambios grandes, resets o teletransportes.

Parametros principales:
  NG_SNAPSHOT_HZ=20
  NG_CLIENT_INTERPOLATION_MS=70
  NG_CLIENT_MAX_EXTRAPOLATION_MS=125
  NG_CLIENT_SMOOTHING_RESPONSIVENESS=18
  NG_CLIENT_SNAP_DISTANCE=210

No aumentes exageradamente la extrapolacion: cuanto mas tiempo inventa visualmente el cliente, mayor puede ser la correccion posterior.


15. STUN / TURN
---------------
Para una prueba basica puedes dejar:

  NG_PUBLIC_ICE_SERVERS_JSON=[]

Para Internet real, algunos NAT/firewalls pueden impedir la conexion WebRTC directa.
En ese caso configura STUN/TURN propios.

TURN es un servicio distinto del Noise Golf Server Relay.
El Relay hace discovery/señalizacion; TURN puede transportar WebRTC cuando no existe ruta directa viable.

No guardes credenciales TURN permanentes sensibles dentro del .env publico del juego.
Para produccion profesional usa credenciales temporales/rotables cuando implementemos esa capa.


16. DIAGNOSTICO RAPIDO
----------------------
Si ONLINE aparece NO DISPONIBLE:

1) Comprueba:
   https://golf.tudominio.com/.env

2) Comprueba:
   https://relay.tudominio.com/health

3) Verifica en .env del juego:
   NG_ONLINE_ENABLED=true
   NG_RELAY_URL=wss://relay.tudominio.com

4) Verifica en .env privado del Relay:
   PUBLIC_WS_URL=wss://relay.tudominio.com
   ALLOWED_ORIGINS=https://golf.tudominio.com
   TRUST_PROXY=true

5) Comprueba NGINX:
   sudo nginx -t
   sudo systemctl reload nginx

6) Reinicia el Relay si modificaste su .env.

7) Abre las herramientas de desarrollador del navegador y revisa Console + Network -> WS.
